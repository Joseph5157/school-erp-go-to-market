# Implementation Guide

<p class="erp-draft" data-search-exclude><strong>Draft.</strong> Verify against the deployed build before sharing.</p>

This guide is for the team that brings a school onto School ERP: the implementation lead and the school's nominated administrator. It sets out what to do, in what order, and how to check the result before the school goes live.

## Recommended order

| Step | Guide | Outcome |
|---|---|---|
| 1 | [Initial school configuration](initial-configuration.md) | School details, message channel, Academic Year and calendar |
| 2 | [Academic structure](academic-structure.md) | Classes/Grades, Sections, Subjects offered and Terms |
| 3 | [Data preparation](data-preparation.md) | Clean student and guardian data in the import template |
| 4 | [Excel import validation](excel-import.md) | Students, guardians and placements created after review |
| 5 | [Account provisioning](account-provisioning.md) | Office, teacher and guardian logins; assignments and portal access |
| 6 | [Onboarding and acceptance checks](onboarding-acceptance.md) | Each role tested end to end before go-live |

The **Overview** page's setup checklist tracks the same milestones and links to the page that completes each one.

## Before you start

- Agree the go-live date and the first Academic Year with the school.
- Identify who will be the school's administrators, and who approves report card publication.
- Collect the school's class list, subject list, term dates and holiday list.
- Agree where completed school data will be stored securely. **Never** store school data, exports or passwords in shared drives without access control, in chat groups, or in this documentation repository.

## Current product boundaries

Set expectations early. These are outside the current standard product: fees and online payments, automatic SMS/email/WhatsApp delivery, student login, native mobile app, offline use, academic-year bulk rollover, Transfer Certificate (pending school format), transport, library, hostel, payroll, inventory, multi-school operation, ranks, GPA and weighting rules. Record any request for these as a separate decision.
