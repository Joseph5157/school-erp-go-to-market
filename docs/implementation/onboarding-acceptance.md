# Onboarding and acceptance checks

<p class="erp-draft" data-search-exclude><strong>Draft.</strong> Verify against the deployed build before sharing.</p>

Before go-live, walk through each role with the school on the **deployed build** the school will use. Record the product version, the date, who took part and the result of each check in the school's acceptance record, stored securely outside this repository.

!!! warning "Use fictional records for testing"
    Run write-actions such as publishing, withdrawing or correcting against clearly labelled fictional test students, or agree with the school which real actions are part of go-live. Remove or deactivate test records according to the school's decision.

## Setup

- [ ] Every step in the **Overview** setup checklist is complete.
- [ ] School details, Academic Year, calendar, Classes/Grades, Sections, Subjects offered and Terms match the agreed lists.
- [ ] Grading scales have a band from 0% and apply to the right Class/Grades.
- [ ] **Assignment overview** shows no gaps.
- [ ] **Timetable issues** shows no unresolved clashes (if the timetable is used).

## Administrator

- [ ] Register a test Applicant, accept it, progress it to a Student and place it in a Section.
- [ ] Correct a detail with a reason and see it in the correction history.
- [ ] Open a register, submit it, then correct one entry with a reason.
- [ ] Run **Daily absent students**, **Missing attendance** and **Monthly Class/Section summary**.
- [ ] Plan an assessment, have the teacher enter marks, then finalise it.
- [ ] Preview and publish a Term report card for one test student; withdraw it again if agreed.
- [ ] Publish and withdraw a test notice.
- [ ] Issue a test bonafide certificate and check the school details and serial number.
- [ ] Clear a test sign-in lockout.

## Teacher

- [ ] Sign in with a temporary password and change it.
- [ ] **My day** shows the correct Section, timetable and assignments.
- [ ] Take, save as draft, and submit today's attendance.
- [ ] Confirm the submitted register is read-only for the teacher.
- [ ] Enter marks including one Absent and one blank, and save a draft.
- [ ] Write and save a term remark.
- [ ] Confirm the teacher cannot open a Section they are not assigned to.

## Guardian

- [ ] Sign in with a temporary password and change it.
- [ ] See only the children granted, and switch between them.
- [ ] Attendance calendar matches submitted attendance; *Not recorded* days are explained.
- [ ] A published report card is visible and **Download PDF** works.
- [ ] Unpublished marks are not visible.
- [ ] A notice for the child's class is visible; a notice for another class is not.
- [ ] After access is revoked, the child disappears from the portal.

## Security and privacy

- [ ] No shared logins. Every staff member has their own account.
- [ ] Temporary passwords were handed over in person.
- [ ] Import workbooks and exports are stored only in the agreed secure location.
- [ ] Screens shown in training contain no unnecessary personal data.

## Sign-off

Acceptance is recorded by the school and the implementation lead in the school's agreed record. Any failed check is logged with an owner and a date before go-live.
